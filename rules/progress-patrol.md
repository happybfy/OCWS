# 队长巡检与停滞升级（Progress Patrol）

本文档定义小队队长的**进度巡查**职责、停滞阈值与升级权限，目的是避免任务长时间无人处理。

> 分工：计划者做机械巡检（每次心跳查重复/幂等/状态一致性，见 `concurrency-idempotency.md` §4）；队长做进度巡查与停滞裁决；两者不互相替代。

## 1. 适用范围

- 每个 `active` 项目。
- 队长（Captain）为第一责任人；计划者提供状态数据，执行者配合说明。

## 2. 巡检频率

- 每个 `active` 项目每天至少 **2 次**（上午、下午各一次）。
- 关键发布/高风险任务期间，按需提高到每 2 小时一次。
- 巡检必须看：
  - 任务状态与最后更新时间
  - `blocked` / `failed` / 门禁退回
  - 通知积压（`inbox` / `working` 未处理）
  - 队列年龄与预计完成时间

## 3. 停滞阈值与动作

| 停滞时长 | 动作 | 权限 |
|---|---|---|
| 2h 无进展 | 联系计划者/执行者，确认卡点 | 询问、催办 |
| 4h 无进展 | 可重试、队内换人、拆分、挂起 | 队长自决（L1） |
| 8h 无进展或影响生产 | 升级 Sponsor | 人类裁决（L3） |
| 同类失败连续 2 次 | 按结构性缺陷上报，暂停同类重试 | 队长 + 计划者 |

- 阈值从**最后一次有效产出**起算，不以“通知已发”或“正在运行”代替进展。
- 生产写、删除、跨账号操作仍按 `authorization-boundary.md` 的 L3 处理，队长不得自行批准。

## 4. 队长权限边界

可以：

- 重试、队内换人、拆分任务、挂起任务
- 调整执行顺序与限速
- 要求计划者补发/撤回通知

不可以：

- 改范围、改验收标准
- 批准权限、凭据、生产写
- 绕过计划者直接派工
- 代替门禁做验收结论

## 5. 记录

每次巡检写巡检日志（`20-robots/<captain>/logs/YYYY-MM-DD.md`）：

- 时间、项目、任务、当前状态
- 最后有效产出的时间
- 采取的动作与依据
- 下次检查点

## 6. 升级路径

1. 队长 → 计划者（补数据/补通知/换人）
2. 队长 → 主管（跨队协调、资源冲突、规则解释）
3. 队长/主管 → Sponsor（权限、生产变更、终止/取消）

## 7. 向人类定期简报（2026-11-20 起）

小队有任务在执行时，队长须在**任务未完成期间**，于**非休息时间（每日 8:00–20:00）**内，**每 4 小时**向人类（Sponsor）发送一次任务简报。

简报至少包含：

- 任务号 + 当前状态
- 本周期进展（完成 / 进行中 / 阻塞）
- 已处理进度（条数 / 百分比，如适用）
- 阻塞点 / 风险（若有）
- 下一步 + 预计完成时间

说明：

- 首次简报自任务进入执行状态起 4 小时内发出，之后每 4 小时一次，直至任务归档 / 完成。
- 休息时间（20:00–次日 8:00）不发送；任务跨休息时间时，恢复后自 8:00 起按 4 小时节奏继续。
- 简报直达人类，同时抄送主管。
