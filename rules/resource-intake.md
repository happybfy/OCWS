# 资源添加方式（A 流程 / B 流程）

> 版本：v1（2026-11-22）
> 依据：Sponsor 2026-11-22 确认（命名：A流程 / B流程）
> 关联：`云笈导入规范`、`authorization-boundary.md`、`progress-patrol.md`

## 0. 定义

云笈资源添加分两种流程，后续任务沟通**统一用简称：A 流程 / B 流程**，不再展开描述步骤。

---

## 1. A 流程（全流程：分享链接 → 转存 → 完整导入）

**适用**：拿到外部分享链接（百度网盘等），需要转存 + 完整建资源。

**输入**：分享链接 + 提取码

**步骤**

1. 链接有效性核实（失效 / 提取码错 / 违规拦截 → 剔除并留痕）
2. 转存到 **C 侧**（生产环境，默认目标账户）
3. 云笈导入：
   - 建资源（title / category / description / uid / status / source_url）
   - 分类三级判定（不确定归「其他」）
   - 封面：源包内图优先 → 文生图（`qwen-image-3.0`，600×800 JPEG q60 ≤150KB）
   - README（元数据 + 末行源链接）
   - 广告文件（云笈网 data-cat.cn）
   - 索引（批次台账 + 全局台账）
4. 验收：门禁复算 + 公开访问 HTTP 200

**产物**：resource_id + 封面 + README + 广告文件 + 索引

---

## 2. B 流程（直导：已有数据 → 直接建资源）

**适用**：已有结构化数据 / 资源记录，直接建资源，不做转存和加工。

**输入**：现成数据（title / category / description / url 等字段）

**步骤**

1. 数据校验（字段完整、uid 计算、查重）
2. 直接建资源（写 resource + 分类），url 用提供的数据
3. **不做**：转存、封面、README、广告文件
4. 验收：数据核对 + 公开访问 HTTP 200

**产物**：resource_id（纯数据记录）

---

## 3. 对比

| 环节 | A 流程 | B 流程 |
|---|---|---|
| 转存 | ✅ | ❌ |
| 建资源 / 分类 | ✅ | ✅ |
| 封面 | ✅（源图 or 文生图） | ❌ |
| README | ✅ | ❌ |
| 广告文件 | ✅ | ❌ |
| 索引 | ✅ | ✅（可只记全局台账） |

---

## 4. 使用约定

- 派单 / 沟通直接写「A 流程」或「B 流程」，不再重复步骤
- A 流程细则见 `云笈导入规范`；B 流程按本文件执行
- 两者都遵守：生产只读排查优先、不覆盖三步法、留痕、发布流程
