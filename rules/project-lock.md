# 项目级串行（Project Lock）

本文档定义 OCWS 的**一队一项目**约束：同一小队在同一时刻只能有一个 `active` 项目，避免跨项目上下文混串、授权冲突和事实源污染。

> 与 `concurrency-idempotency.md` 的区别：后者管同一项目内的并发写入与幂等；本文档管**项目之间的串行**。

## 1. 适用范围

- 适用于每个小队（计划者 + 执行者 + 门禁者 + 队长）。
- 一个项目可由多个小队参与；**每个小队各自持有自己的项目锁**，互不替代。
- 共享基础设施（GitLab、NFS、registry、ESXi 等）的运维不受本文档限制，但必须走 `ops` 通道（见 §4）。

## 2. 锁的定义

- 小队处于 `locked` 状态的条件：其名下存在任意**未归档**任务（`new / assigned / working / done待门禁`）。
- `locked` 期间：
  - 不得派发其他项目的任何任务（含 `new`、`assigned`）；
  - 不得为其他项目创建执行批次或通知；
  - 只允许只读排查、归档收尾和本项目的任务。
- `unlocked` 条件：该项目所有任务均为 `archived`，或项目被显式 `parked` 并完成交接。

## 3. 项目切换流程（硬门）

1. 当前项目任务全部 `archived` 或 `parked`，并写 `closure_reason`；
2. 产出交接说明：未完成项、风险、回滚点、遗留证据位置；
3. 计划者确认锁已释放；
4. 通知 Sponsor 与队长；
5. 之后才允许为新项目建卡、派发。

未完成上述步骤即派发新项目任务 = **违规派发**，执行者可拒收，门禁可拒绝验收。

## 4. 例外

- **共享基础设施运维**：走独立 `ops` 通道，串行执行、限时、单独留痕，不计入项目锁；同一时刻只允许一个 ops 任务。
- **紧急跨项目修复**：需 Sponsor 书面授权 + 明确时间盒（建议 ≤2 小时）；到期未完成必须回原项目或转新卡。
- **只读排查**：不受锁限制，但不得写入、不得派发执行任务。

## 5. 执行点

| 角色 | 检查 |
|---|---|
| 计划者 | 派发前检查小队锁；锁定则拒绝派发 |
| 队长 | 巡检时核对 `project.md` 的 `当前状态` 与任务归档情况 |
| 门禁者 | 验收时核对 `project_id`，跨项目任务直接退回 |
| 主管 | 抽查锁状态；处理例外授权 |

## 6. 记录

- `project.md` 的 `当前状态` 必须为 `planning / active / on-hold / parked / done / archived` 之一。
- 项目切换、例外授权、ops 任务写入对应 `project.md` 变更记录与 `outbox/`。
